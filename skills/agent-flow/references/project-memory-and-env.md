# Память проекта и рабочая среда

## Чтение контекста

Начните с текущего запроса, проектных инструкций и названной задачи или плана. Прочитайте относящиеся к работе части To Do, Lessons и Implementation Notes, затем необходимые исходники и конфигурацию. Сначала ищите известный файл или раздел; не перечитывайте весь репозиторий и историю при каждом продолжении.

Проверьте зависимости текущей задачи. Не начинайте зависимую реализацию, пока отсутствует необходимое продуктовое решение или вход предыдущего шага. Уточняйте у пользователя только существенный вопрос, который нельзя разрешить из доступных источников.

Для нескольких репозиториев определите их реальные корни, общие контракты и владельцев. Требования задачи выбираются в существующем документе; нужные дополнительные источники объявляются context inputs. Не копируйте их текст в новую DoD-матрицу.

## Три файла памяти

To Do, Lessons и Implementation Notes — постоянная память выполнения проекта. Используйте существующие файлы и соглашения проекта. Если они находятся в `.agent-work/tasks/`, обычные имена — `todo.md`, `lessons.md`, `implementation-notes.md`.

- To Do хранит задачи, их критерии, зависимости и фактическое состояние.
- Lessons хранит применимые уроки: условие, обнаруженную причину и полезное действие.
- Implementation Notes хранит решения и сведения, нужные для продолжения реализации.

Обновляйте файлы напрямую, точечно и по факту. Не создавайте их автоматически ради каждого запроса. Сохраняйте пользовательское содержимое и полезную историю между чатами, провайдерами и обновлениями Agent Flow.

Не импортируйте память в базу прогона, не генерируйте зеркальные блоки, Evidence Records, счётчики полезности или автоматическое продвижение уроков. Временно нужные доказательства живут в отчёте текущего исполнителя. В память переносится вывод, полезный будущей работе, со ссылкой при необходимости.

Отметка выполненного пункта To Do не меняет текст критериев. Изменение самих критериев требует повторной проверки относящегося к ним результата.

## Среда и разрешения

Исследуйте конфигурацию до запуска приложения, тестов и сервисов. Команды выполняются в реальном выбранном checkout; отдельная полная копия для каждой проверки не требуется. Обычные временные и игнорируемые результаты инструментов допустимы в пределах разрешений пользователя.

Не запускайте автоматически контейнеры, серверы, миграции, установку зависимостей и браузер. Выбирайте минимальную разрешённую проверку. Недоступная проверка остаётся неподтверждённой, а не положительной.

Поручение на локальные правки не разрешает commit, push, merge, сообщения людям, release или deploy. Ранее данное разрешение сохраняется в пределах задачи; не запрашивайте его повторно без изменения условий.

Секреты и значения локальных env не копируйте в отчёты. Используйте пути, названия переменных и безопасные диагностические факты.

## Прерывания

Перед продолжением прочитайте текущее состояние через `journal.py read` и проверьте фактические исходники и native-результаты. Точный повтор записи использует тот же operation ID и аргументы.

Если внешняя команда могла выполниться до сбоя, не запускайте её вслепую повторно. Сначала установите результат; если он недоступен, укажите неопределённость. SQLite восстанавливает согласованность своих записей, а не откатывает исходники или действия внешних сервисов.
