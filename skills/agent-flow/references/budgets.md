# Масштаб работы

По умолчанию выбирайте `light`: один автор и минимальные необходимые проверки. Масштаб влияет на координацию, а не формат хранения.

- `light` — ограниченная правка, анализ или консультация. Дополнительные implementation workers обычно не нужны.
- `standard` — самостоятельные части задачи, которым полезны отдельные владельцы или независимое исследование.
- `release` — высокая цена ошибки: публикация, безопасность, платежи, существенная миграция. Нужны относящиеся к риску специалисты и проверки, а внешние действия требуют разрешения.

Для изменения файлов при любом масштабе обязательны независимые QA и reviewer. Это не повод автоматически повышать budget или создавать дополнительные документы.

Используется один актуальный SQLite-контракт. Короткая консультация не требует журнала.

Повышайте масштаб только по конкретной зависимости, риску или поручению пользователя. Не увеличивайте число агентов из-за количества файлов и не запускайте их для заполнения обязательных секций.
