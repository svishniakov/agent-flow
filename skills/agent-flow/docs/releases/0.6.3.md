# Agent Flow 0.6.3

Document status: done

This release resolves the third independent review round: three regressions
found in the 0.6.2 fixes, plus the corresponding strengthenings. Every fix
carries a regression test that fails on the unfixed code, and the import
migration was verified against receipts written by the actual 0.6.2 code.

- **Covers resolve per document.** A lane's section coverage is resolved for
  each candidate document independently: a hash-bound receipt is authoritative
  (an empty cover set is data, not absence), otherwise the current document's
  writer-rendered markers apply. `None` now means only "no data anywhere"
  (legacy/flat), so a current handoff without sections fails the required
  coverage check instead of silently skipping it, and 0.6.0 journals with
  coverage spread across handoff and report read fully.
- **Strict audit treats a missing receipt as missing evidence — with the
  supported text carrier intact.** When no receipt binds the current handoff
  bytes, evidence declared literally (path + SHA-256) inside the current
  handoff still satisfies the completeness check; a receipt that does exist
  stays decisive, and a rewritten handoff without either carrier is rejected.
- **Evidence Records import is faithful and resumable.** Canonical comparison
  excludes only the import date stamp, so a conflicting user `Provenance`
  refuses safely; explicit counters (including zero) are stored as absolute
  values instead of being approximated by derived deltas; interrupted imports
  complete stage-by-stage on re-run; imports partially written by 0.6.2
  (carry-over counter events) are recognized by their saved operation payloads
  and normalized atomically — ordinary same-counter events are never removed,
  conflicts are checked before any mutation, and real applications recorded
  between attempts are preserved.
- **Carry-over proof is exact.** A 0.6.2 carry-over event is recognized only
  when a saved operation's payload hash matches the canonical payload rebuilt
  from every persisted event field — including `active` when present — with
  one receipt proving at most one event. An ordinary event that differs only
  by `active: false` is kept, and the record's Active flag stays intact.
- **Reduced sources are refused.** For rows written by 0.6.2, each counter is
  checked with the 0.6.2 writer arithmetic: at most `max(0, T − B)` proven
  carry-overs are compatible with a source whose target is `T` over derived
  base `B`. More proof than the source allows aborts the import with
  `import conflict: <id> counters below already journaled carry-over`, before
  any normalization runs and without touching the manual notes; the same check
  is repeated inside the normalization transaction.
- **Editing a record keeps its non-request state.** Updating an Evidence
  Record preserves its imported counter base, custom extra fields, and active
  flag; an explicit `active` in the request overrides, and outcome events keep
  priority in computing current activity.

## Compatibility fixtures

`skills/agent-flow/testdata/compat/` now pins journals produced by the actual
writers of previous releases, each with its manual source and a manifest
(producer tag, commit SHA, scenario, stop point, generation method, per-file
SHA-256):

- `060-covers` — v0.6.0 (`97afe68`): section covers split between a hash-bound
  handoff receipt and a lane-report receipt that predates the hash binding.
- `062-complete` — v0.6.2 (`170e770`): finished import of `Helpful: 3` (two
  carry-over events), reused for the reduced-source refusal checks.
- `062-partial` — v0.6.2: import stopped after the first of two carry-overs.
- `062-active-event` — v0.6.2: an ordinary `active: false` helpful event
  recorded through the 0.6.2 API before the first carry-over, then stopped.
- `062-zero` — v0.6.2: finished import of an explicit `Helpful: 0`.

The test loader copies a fixture into a scratch directory and relocates only
`run_state.source_root`/`run_state.logical_root`, proving by a full database
comparison that nothing else changed; fixture files are checksum-verified
before and after each test. These fixtures follow the existing packaging
rules: excluded from the plugin ZIP like the rest of `testdata`, and included
in the standalone Skills CLI installation (`npx skills add`).

Verification on this change: all 24 package test scripts plus the root
release/packaging suites pass (including 156 checks in `test-journal-io.py`
and 68 in `test-verification-evidence.py`), `validate-rule-consistency.py` is
clean, golden traces are untouched, and the full `check-all.py` battery passes.
Every fix above carries regression tests that fail on the unfixed code.
