# Agent Flow 0.4.0

Document status: done

This release consolidates the journal entry points: agents pass only semantic
facts, and the writer generates formats, hashes, projections, and views. A
compact change-run now takes about 12-15 journal calls instead of 19-21, with
zero hand-written JSON artifacts. It is a breaking change for saved command
sequences.

- **Breaking: three scripts removed.** `append-timeline.py`,
  `record-handoff-state.py`, and `record-lane-boundary.py` are deleted along
  with their shims. Their jobs moved into existing entry points:
  - Commit events are recorded through `journal.py record --kind event` with a
    40-hex `commit_hash` field in the request JSON.
  - Boundary evidence is written atomically by the worker conclusion call:
    `record-agent-trace.py --prepare-conclusion --authored-path <path>
    [--coauthor lane:path] ...` computes handoff and edit-evidence SHA-256 from
    the journal itself, so no manual declaration JSON is published anymore.
  - Handoff state is a writer-computed projection of `lane-map.json`, updated
    at every assignment event including lane declarations and
    `resolve-obligation`; batch metadata travels as optional
    `record-agent-trace.py` fields (`--batch-id`, `--batch-item`, `--from`,
    `--to`, `--task`). There is no manual status synchronization.
- **Handoff State Gate is unconditional.** For durable lane-map runs the gate
  no longer needs an opt-in; `init-run.py` does not set
  `handoff_state_required` anymore (the flag stays readable for older lane
  maps, and flat fixtures remain flag-gated).
- **`--verification-json` is a patch.** Callers pass only the fields that
  change, for example `{"task_kind": "change"}`; omitted fields are preserved,
  unknown fields are rejected, and derived values (reference SHA-256,
  `result_files`, `result_hash`, selected QA/reviewer) are recomputed by the
  recorder. No capture file is carried between calls.
- **Flagless finalize.** All four `journal.py finalize` flags
  (`--expected-run-uuid`, `--expected-revision`, `--expected-generation`,
  `--operation-id`) are optional: values default to the current journal
  snapshot and the operation ID is generated and printed in the receipt.
  Passed flags remain explicit compare-and-swap assertions.
- **Generated views.** `checks/coverage-matrix.md` is regenerated by the
  writer from `lane-map.json` at every lane mutation and is writer-owned; the
  `coverage` record kind is removed. The writer also emits the
  `Engineering Simplicity`, `Boundary Evidence`, and `Continuation Summary`
  sections of `final.md` (including historical/new worker lanes) from recorded
  facts, closing the gap where a durable run could not pass the full audit on
  writer-generated output.
- **Consistency guard extended.** `validate-rule-consistency.py` now fails the
  build if agent-facing documents reintroduce any of the three removed
  commands.

No validator check was removed: golden traces and all gate rules are unchanged.
