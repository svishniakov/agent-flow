# Agent Flow 0.5.0

Document status: done

This release replaces prose-grep acceptance checks with structured facts.
Section coverage is declared data, not text pattern matching. It is a breaking
change for the journal request contract.

- **Breaking: `covers` is required for named audit sections.** Section records
  in handoff, lane-report, and architecture-outcome requests accept
  `covers: [ids]` (kebab-case, unique). For the named audit sections —
  `Engineering Simplicity`, `Boundary Evidence`, `Architecture Compliance`,
  `Architecture Invariants`, `Engineering Simplicity Scope`, `Architecture
  Matrix Mismatches`, `Contract Drift`, `Risk Mitigation Review`, `Risk
  Resolution Verification`, `Risk Resolution Review`, `Continuation
  Revalidation`, `Continuation Review`, `Harness Evaluation Review`, the
  recovery review sections, and claim owner sections — `covers` is mandatory
  and non-empty. The writer renders `- Covers: \`id\`` lines before the section
  text, and the validator reads coverage from receipts instead of grepping
  markdown. Flat legacy handoffs without covers data keep their
  already-validated JSON facts.
- **Structured fields instead of phrase matching.** Fixed simplicity
  remediation lives in `architecture_compliance.engineering_simplicity`
  (`findings`/`actions` arrays, `status=fixed`); retained dependencies and
  abstractions live in `engineering_simplicity.retained` with `kind`
  (`dependency`/`abstraction`) and a selected capability id; reviewer verdicts
  on scope are declared as covers ids (`engineering-simplicity`, fixed worker
  lane ids, primary surface ids, `rejected-peripheral-only-closure`) instead
  of specific Russian or English phrases that a reviewer had to guess.
- **Contract ids from receipts.** Claim and acceptance ids come from the
  architecture outcome request fields (`claim_evidence_ids`,
  `acceptance_criteria_ids`) and are read back from the outcome receipt — no
  more parsing the contract markdown.
- **Tautological render checks removed.** In durable storage v3, writer-owned
  bytes (final.md sections, contract sections, coverage matrix) are guaranteed
  by construction: they cannot change except through the deterministic writer.
  Forgery protection lives at the storage layer — writer-owned paths,
  receipts, and hash bindings — so grepping the rendered markdown for the same
  facts added no assurance and is deleted. `validate-run.py` shrinks by 723
  lines (−518 net) with no loss of coverage: every removed check was either a
  duplicate of an existing JSON validation or received a covers/field
  equivalent.
- **Section input through `--sections-file`.** `--prepare-conclusion` accepts
  typed `[{section, summary, covers}]` JSON for generated conclusion headings;
  the writer-owned `Verification Gate Results` section remains generated, not
  caller-supplied.

Gate names use the seven contours introduced in 0.4.1. No artifact format or
filename changed.
