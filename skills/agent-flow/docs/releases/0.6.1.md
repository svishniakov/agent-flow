# Agent Flow 0.6.1

Document status: done

This bugfix release addresses six findings from an independent review of the
0.2.3–0.6.0 consolidation series. Each fix carries a regression test that
fails on the unfixed code.

- **Release builds are hermetic.** The plugin archive is assembled from the
  exported tree of the stated commit (`git archive`), not the working
  checkout, so untracked or git-ignored files (for example a stray `.env.*`)
  can no longer leak into a release ZIP. Release builds require
  `--commit-sha`; local builds without it print an explicit warning.
- **Handoff coverage binds to current document bytes.** Section `covers` are
  accepted only from receipts whose recorded hash matches the current handoff
  bytes; rewriting a report can no longer inherit coverage from a superseded
  draft. Receipts for lane reports now record the document hash.
- **Evidence ownership is strict.** A receipt missing the boundary key no
  longer matches a `None` boundary query, so evidence recorded against a
  different handoff cannot satisfy this one.
- **Evidence Records import is safe across runs.** Import reads only the
  manual zone of the notes file (generated blocks of other runs are excluded),
  rejects manual records whose ids are already journaled elsewhere, and a
  re-run completes an interrupted import instead of getting stuck.
- **Batch mode engages for normally declared lanes.** Passing batch metadata
  now selects batch mode even when the lane's seeded handoff state says
  `task`; conflicting explicit mode and batch parameters are still rejected.
- **The updater stops simulating checks.** Post-update install and full checks
  use the real paths inside `skills/agent-flow/scripts/`; a missing mandatory
  check fails the update instead of printing a skip and returning success.
