# Проверки перед коммитом и после push

Document status: done

Локальный `pre-commit` запускает полный `scripts/check-all.py` для индекса Git,
то есть подготовленных к коммиту файлов. Неподготовленные изменения остаются
в рабочем каталоге и не влияют на результат проверки.

## Подготовка

Команды выполняются из корня исходного Git-репозитория Agent Flow.
Установленная копия скилла без исходного репозитория для этого не подходит.

Нужны Python с модулем `venv`, Git, Node и Codex CLI. Версии инструментов
и библиотек записаны в `skills/agent-flow/check-tools.json` и
`skills/agent-flow/requirements-codegraph.txt`. Подготовка проверяет версии,
создаёт локальное окружение Python, устанавливает закреплённые зависимости
и локальные Skills CLI и pnpm. Установка требует сети и выполняется явно.

Укажите путь к подготовленному браузеру требуемой версии:

```sh
python3 scripts/prepare-check-environment.py \
  --prefix "$PWD/.git/agent-flow-checks" \
  --browser /absolute/path/to/chrome-headless-shell
```

Затем выполните напечатанную команду подключения hook. Её форма:

```sh
python3 scripts/install-pre-commit.py \
  --python "$PWD/.git/agent-flow-checks/bin/python3" \
  --tool-bin "$PWD/.git/agent-flow-checks/bin" \
  --browser /absolute/path/to/chrome-headless-shell
```

Повтор той же настройки безопасен. Hook действует только в этом клоне.
Он хранит копию исполнителя в `.git/hooks/agent-flow-check-index.py`, поэтому
неподготовленная правка исполнителя в рабочем каталоге не подменяет проверку.
Если перемещено окружение или изменён сам исполнитель, потребуется явное
обновление установленной копии после проверки существующих файлов.

Существующий `core.hooksPath`, чужой `pre-commit` или отличающийся файл
исполнителя останавливают настройку. Их содержимое и Git-конфигурация сохраняются.
Для интеграции в свой hook добавьте вызов `scripts/check-index.py` подготовленным
Python, передайте каталог инструментов через `PATH` и путь браузера через
`AGENT_FLOW_TEST_BROWSER`. Ненулевой код исполнителя должен останавливать hook.
Сначала проверьте объединённый hook во временном клоне.

## Обычная работа

```sh
git add path/to/file
git commit -m "Описание изменения"
```

Hook создаёт отдельный временный Git-репозиторий из индекса и запускает весь
канонический набор. Проверяются также частично добавленные файлы. Файлы
извлекаются из Git-объектов без фильтров checkout, смены переводов строк
и исключений `export-ignore`.

Отсутствующий инструмент, неподходящая версия, пропущенная обязательная проверка
или ошибка теста запрещают коммит. Hook не устанавливает зависимости.
Sandbox-проверки запускают команды через Codex CLI, без запроса к платной модели.

При успехе, ошибке, `Ctrl+C`, `SIGTERM` и `SIGHUP` временная копия удаляется.
Исходные файлы и индекс исполнитель не переписывает. Если другой процесс
изменил индекс во время проверки, коммит отклоняется: повторите его после
сверки подготовленных файлов. Принудительный `SIGKILL` и отключение питания
не позволяют программе выполнить очистку; оставшийся каталог имеет префикс
`agent-flow-index-` в системном временном каталоге.

Подмодули и ссылки за пределы временной копии дают явный отказ. Рекурсивный
запуск исполнителя тоже запрещён. Git позволяет пользователю явно обойти
локальный hook. Проверка на GitHub выполняется отдельно после push.

## Проверка механизма

`scripts/test-check-index.py` выполняет пробные коммиты в маленьких временных
репозиториях и проверяет сохранность файлов, индекса и очистку после прерывания.
Эти сценарии входят в полный набор. Они проверяют поведение hook; полноценный
прогон `check-all.py` во время пробного коммита фиксируется отдельно при приёмке.

Полный набор запускается на macOS. Linux требует совместимого Codex sandbox:
выбранный контейнерный runner отказал с `bwrap: No permissions to create a new
namespace`. Пользователь разрешил второй прогон в отдельном чистом checkout
с отдельным окружением на том же Mac. Это не проверка на другой машине или чистой
операционной системе. Linux-прогон успешным не объявляется; привилегии контейнера и ядро
ради проверки не меняются. Длительность каждого полного прогона печатает hook.

## Проверки и сборки на GitHub

Workflow `Push checks and distributions` запускается после обычного `push`
в любую ветку, включая изменения только документации. Если push содержит несколько
коммитов, проверяется его вершина: checkout явно закреплён на `GITHUB_SHA`.
Удаление ветки не создаёт устанавливаемую сборку. Следующий push не отменяет
и не заменяет предыдущий запуск.

На `macos-15` ARM64 явно устанавливаются версии Python, Node, Codex CLI и браузера
из `check-tools.json`; Go 1.27.1 и Bun 1.3.14 закреплены в workflow.
Инструменты размещаются в уже разрешённых sandbox-каталогах. Для Node сохраняется
неизменённая копия его OpenSSL-конфига; права sandbox не расширяются.
Существующий `prepare-check-environment.py` готовит закреплённые зависимости.
Затем выполняется тот же `python3 scripts/check-all.py`,
что использует pre-commit. Codex sandbox tests выполняют реальные команды
в песочнице с пустым профилем, без модели, аккаунта и пользовательских API-ключей.
Отсутствующий инструмент, ошибка или пропуск обязательной проверки завершают
запуск неуспешно.

После полного успеха существующий сборщик создаёт два ZIP. Проверка поставки
сверяет состав, общие файлы, версию, исходный SHA и SHA-256, затем проверяет
распакованные пакеты. Только после её успеха GitHub сохраняет четыре явно
перечисленных файла: оба ZIP, метаданные и контрольные суммы. Упавший запуск
не публикует устанавливаемые архивы; диагностика остаётся в его логах.
Workflow имеет только `contents: read` и не записывает коммиты или теги.

Версия тестовой сборки имеет вид `X.Y.Z-dev.RUN.ATTEMPT`: базовая версия взята
из `.codex-plugin/plugin.json`, RUN и ATTEMPT обозначают запуск GitHub и его
попытку. Исходный манифест не меняется. Одинаковые входы дают одинаковые байты;
новый запуск или повторная попытка получают отдельную версию. Имя скачиваемого
результата содержит полный commit SHA. Это тестовые сборки, а не стабильные релизы.

Встроенные директивы GitHub, например `[skip ci]`, `[skip actions]` или
`skip-checks: true`, могут исключить запуск. Такой push не проверен и не даёт
новую сборку. Для восстановления отправьте следующий обычный коммит без директивы.
Успех старого запуска не подтверждает пропущенный SHA.

Скачать сборку можно на странице успешного запуска, в разделе Artifacts.
Срок хранения в workflow: 14 дней, в пределах политики репозитория.
Порядок проверки и установки описан в [инструкции](installation.md#сборки-после-push).
