# Проверки перед коммитом и после push

Document status: done

Локальный `pre-commit` запускает полный `skills/agent-flow/scripts/check-all.py` для индекса Git,
то есть подготовленных к коммиту файлов. Неподготовленные изменения остаются
в рабочем каталоге и не влияют на результат проверки.

## Подготовка

Команды выполняются из корня исходного Git-репозитория Agent Flow.
Установленная копия скилла без исходного репозитория для этого не подходит.

Нужны Python с модулем `venv`, Git и Node. Версии инструментов
записаны в `skills/agent-flow/check-tools.json`. Подготовка проверяет версии,
создаёт локальное окружение Python и локальный Skills CLI.
Установка требует сети и выполняется явно.

```sh
python3 skills/agent-flow/scripts/prepare-check-environment.py \
  --prefix "$PWD/.git/agent-flow-checks"
```

Затем выполните напечатанную команду подключения hook. Её форма:

```sh
python3 scripts/install-pre-commit.py \
  --python "$PWD/.git/agent-flow-checks/bin/python3" \
  --tool-bin "$PWD/.git/agent-flow-checks/bin"
```

Повтор той же настройки безопасен. Hook действует только в этом клоне.
Он хранит копию исполнителя в `.git/hooks/agent-flow-check-index.py`, поэтому
неподготовленная правка исполнителя в рабочем каталоге не подменяет проверку.
Если перемещено окружение или изменён сам исполнитель, потребуется явное
обновление установленной копии после проверки существующих файлов.

Существующий `core.hooksPath`, чужой `pre-commit` или отличающийся файл
исполнителя останавливают настройку. Их содержимое и Git-конфигурация сохраняются.
Для интеграции в свой hook добавьте вызов `scripts/check-index.py` подготовленным
Python и передайте каталог инструментов через `PATH`.
Ненулевой код исполнителя должен останавливать hook.
Сначала проверьте объединённый hook во временном клоне.

## Обычная работа

```sh
git add path/to/file
git commit -m "Описание изменения"
```

Hook создаёт отдельный временный Git-репозиторий из индекса и запускает весь
канонический набор. Проверяются также частично добавленные файлы. Файлы
извлекаются из Git-объектов без фильтров checkout, смены переводов строк
и исключений `export-ignore`.

Отсутствующий инструмент, неподходящая версия, пропущенная обязательная проверка
или ошибка теста запрещают коммит. Hook не устанавливает зависимости.

При успехе, ошибке, `Ctrl+C`, `SIGTERM` и `SIGHUP` временная копия удаляется.
Исходные файлы и индекс исполнитель не переписывает. Если другой процесс
изменил индекс во время проверки, коммит отклоняется: повторите его после
сверки подготовленных файлов. Принудительный `SIGKILL` и отключение питания
не позволяют программе выполнить очистку; оставшийся каталог имеет префикс
`agent-flow-index-` в системном временном каталоге.

Подмодули и ссылки за пределы временной копии дают явный отказ. Рекурсивный
запуск исполнителя тоже запрещён. Git позволяет пользователю явно обойти
локальный hook. Проверка на GitHub выполняется отдельно после push.

## Проверка механизма

`scripts/test-check-index.py` выполняет пробные коммиты в маленьких временных
репозиториях и проверяет сохранность файлов, индекса и очистку после прерывания.
Эти сценарии входят в полный набор. Они проверяют поведение hook; полноценный
прогон `check-all.py` во время пробного коммита фиксируется отдельно при приёмке.

Полный набор запускается на macOS и Linux. Длительность каждого полного прогона печатает hook.

## Проверки и сборки на GitHub

Workflow `Push checks and distributions` запускается после обычного `push`
в любую ветку, включая изменения только документации. Если push содержит несколько
коммитов, проверяется его вершина: checkout явно закреплён на `GITHUB_SHA`.
Удаление ветки не создаёт запуск. Запуск того же ref ждёт завершения предыдущего
и не отменяет его.

На `ubuntu-24.04` явно устанавливаются версии Python, Node и Skills CLI
из `check-tools.json`. Затем выполняется тот же
`python3 skills/agent-flow/scripts/check-all.py`, что использует pre-commit.
Отсутствующий инструмент, ошибка или пропуск обязательной проверки завершают
запуск неуспешно. Обычный push не создаёт устанавливаемых артефактов.

Встроенные директивы GitHub, например `[skip ci]`, `[skip actions]` или
`skip-checks: true`, могут исключить запуск. Такой push не проверен.
Для восстановления отправьте следующий обычный коммит без директивы.
Успех старого запуска не подтверждает пропущенный SHA.

## Совместимость сохраняемых представлений

Изменение сохраняемого представления журнала или project memory (схема
документов, receipts, счётчиков, covers и т.п.) сопровождается фикстурой
совместимости: журнал и ручные заметки создаются реальным writer прежнего
релиза (git worktree нужного тега; исторические receipts не конструируются
и не исправляются вручную) и складываются в
`skills/agent-flow/testdata/compat/<сценарий>/` вместе с manifest (тег и
SHA коммита-производителя, сценарий, точка остановки, способ генерации,
контрольные суммы файлов). Новый код обязан читать или мигрировать такие
фикстуры в тестах. Тестовый загрузчик копирует фикстуру во временный каталог
и переустанавливает только корни окружения (`run_state.source_root` и
`run_state.logical_root`); любое иное изменение содержимого базы запрещено
и проверяется сравнением до/после. Эти фикстуры следуют общим правилам
`testdata`: не входят в ZIP плагина и входят в standalone-установку через
Skills CLI.

## Пронумерованный выпуск плагина

Публичный ZIP плагина появляется при push тега `vX.Y.Z`, совпадающего с версией
`.codex-plugin/plugin.json`. Коммит тега должен входить в историю удалённой
`main`. Теги с суффиксами или ведущими нулями не проходят проверку выпуска.

Тег запускает тот же полный набор тестов. Затем `scripts/build-plugin.py`
создаёт единственный `agent-flow-X.Y.Z-codex-plugin.zip` и проверяет записанный
архив: перечитывает его, сверяет состав и байты со свежим снимком исходников
и прогоняет установленный пакет во временном профиле. После этого
`scripts/publish-skill-release.py` создаёт черновик Releases, загружает ZIP,
скачивает его обратно и сравнивает содержимое. Только после успеха он публикует
релиз. При сбое черновик остаётся для диагностики. Повтор завершает только
совпадающий черновик; готовый релиз сверяет без перезаписи. Расхождение SHA,
байтов или списка файлов останавливает выпуск. Не перемещайте тег для исправления
опубликованной версии: подготовьте новую версию.

В описании релиза находятся ссылка на ZIP плагина, его SHA-256 и команда
`npx skills add` для отдельного скилла. GitHub автоматически добавляет две ссылки
Source code; они не входят в загружаемые нами файлы.
