# Установка Agent Flow

Document status: done

Установите скилл через npx или скачайте плагин Codex из Releases. Python 3.11 или новее нужен для скриптов настройки.
Node.js и Skills CLI нужны только для установки командой `npx skills add`.

## Зависимость для проверки архитектуры

Architecture Simplicity Guard — отдельный обязательный скилл для архитектора и reviewer. Установите или обновите его при любом способе установки, в том числе при переходе на 0.7.6:

```sh
npx skills add https://github.com/svishniakov/arch-simplicity-guard -a codex -g
```

Селектор вызывается внутри текущей сессии каждого исполнителя Codex; экспорт ролей не выбирает модельное дополнение заранее. Для установки только в текущий проект уберите `-g`.

## Skills для Elixir/Phoenix и Astro

Для задач Elixir/Phoenix архитектор и `elixir-phoenix-worker` используют четыре предметных skill из [igmarin/elixir-phoenix-skills](https://skills.sh/igmarin/elixir-phoenix-skills). Для `astro-worker` выбраны [astro](https://skills.sh/astrolicious/agent-skills/astro) и [astro-best-practices](https://skills.sh/incluud/astro-agent-skills/astro-best-practices); последний также используется архитектором при решениях по Astro.

Установите нужный набор явно. Общая установка Agent Flow не устанавливает эти зависимости автоматически:

```sh
npx skills add igmarin/elixir-phoenix-skills --skill elixir-essentials otp-essentials ecto-essentials phoenix-liveview-essentials -a codex -g
npx skills add astrolicious/agent-skills --skill astro -a codex -g
npx skills add incluud/astro-agent-skills --skill astro-best-practices -a codex -g
```

Для установки только в проект уберите `-g`. Проверить зависимости отдельной роли можно командой `python3 check-agent-deps.py --scope role:elixir-phoenix-worker --strict` или `python3 check-agent-deps.py --scope role:astro-worker --strict` из каталога scripts выбранного пакета. После обновления Agent Flow синхронизируйте роли и начните новую задачу Codex, как описано ниже. Сторонние skills применяются по задаче; API сверяются с версией проекта.

## Отдельный скилл

Для новой глобальной установки из GitHub:

```sh
npx skills add https://github.com/svishniakov/agent-flow -a codex -g &&
python3 ~/.agents/skills/agent-flow/scripts/check-agent-deps.py --post-install &&
python3 ~/.agents/skills/agent-flow/scripts/sync-codex-agent-config.py --output-dir ~/.codex/agents
```

После настройки начните новую задачу Codex. Для установки только в один проект
уберите `-g` и укажите каталог ролей `.codex/agents` внутри этого проекта.

## Плагин Codex

Скачайте `agent-flow-X.Y.Z-codex-plugin.zip` из
[последнего выпуска](https://github.com/svishniakov/agent-flow/releases/latest).
Это единственный файл, который мы прикладываем к релизу. Две ссылки Source code
GitHub добавляет автоматически: они содержат снимок репозитория.
JSON сборки и отдельный файл контрольных сумм остаются в Actions.

Сравните SHA-256 скачанного ZIP с суммой в описании релиза или рядом с файлом
на GitHub:

```sh
shasum -a 256 agent-flow-X.Y.Z-codex-plugin.zip
```

Распакуйте ZIP в отдельный постоянный каталог. Внутри `agent-flow` находятся
`.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json` и `skills/agent-flow`.
В файле `skills/agent-flow/agent-flow-package.json` сверьте `version`
с версией релиза; коммит тега указан на странице релиза. Затем установите плагин:

```sh
codex plugin marketplace add "/постоянный/каталог/agent-flow"
AF_PACKAGE="$(codex plugin add agent-flow@agent-flow --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["installedPath"] + "/skills/agent-flow")')"
codex plugin list --json
```

Команда получает `installedPath` из ответа Codex и сохраняет путь установленного
скилла в `AF_PACKAGE`. Путь версии кэша меняется при обновлении.

```sh
python3 "$AF_PACKAGE/scripts/check-agent-deps.py" --post-install
python3 "$AF_PACKAGE/scripts/sync-codex-agent-config.py" --output-dir "$HOME/.codex/agents"
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --dependencies
```

Создайте новую задачу Desktop. В поле запроса введите `@`, выберите установленный
Agent Flow и отправьте задачу. Выбор плагина означает явный вызов его основного
скилла. Обычный запрос без выбора и текстового маркера не должен запускать процесс.

## Проверка пакета и выбор CLI

`check-installed-package.py --package-only` проверяет контрольные суммы и импорт
модулей, затем создаёт run во временном проекте из установленного пакета.
Учётная запись и настройка ролей для этой проверки не нужны. Полный сценарий
записи и чтения журнала, а также подготовки рабочей копии с контекстом проверяют
тесты дистрибутивов на обоих распакованных архивах.

Если приложение поставляет свой Codex CLI, выберите его явно для нужной команды.
Например, для установленного в `/Applications` ChatGPT:

```sh
AF_CODEX_BIN="/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin"
PATH="$AF_CODEX_BIN:$PATH" codex --version
PATH="$AF_CODEX_BIN:$PATH" codex exec --help
PATH="$AF_CODEX_BIN:$PATH" codex debug models --bundled
```

Проверьте существование этого пути в своей установке. Для команд установки плагина
используйте тот же префикс `PATH`. Это не обновляет глобальный CLI. Каталог
`--bundled` показывает модели и reasoning levels из поставки без обновления с сервера;
проверка не доказывает, что аккаунт может выполнить запрос к модели.

## Роли и конфликты

Генератор сохраняет эталон последней синхронизации в `.agent-flow-baseline.json`
рядом с TOML ролей. Перед записью проверяется весь набор. Чужой одноимённый файл,
ручная правка управляемого файла, повреждённый эталон или символическая ссылка
останавливают команду до первой записи. Пути конфликтов выводятся в ошибке.

Сохраните конфликтующие файлы в своей резервной копии. Сравните их с новой ролью;
если решили заменить конкретный файл, перенесите его из каталога ролей и повторите
синхронизацию. Не удаляйте весь каталог `agents`. Старые файлы без эталона можно
принять только при полном совпадении с новой генерацией; их байты не переписываются.
Файлы с прежним служебным заголовком и отличающимся содержимым тоже сохраняются.

`--check` проверяет настройку без записи. Повторная синхронизация неизменного
пакета безопасна. Проверка пакета также обнаруживает несовпадающие роли проекта,
которые могли бы перекрыть глобальные. Недостающие дополнительные скиллы показаны
отдельным отчётом; установка пакета не подключает сервисы и не устанавливает их молча.

## Выбор одной формы и обновление

Проверка также останавливается при явных объявлениях ролей Agent Flow в
`config.toml`, включая именованные профили (`$CODEX_HOME/<имя>.config.toml`)
и настройки родительских каталогов
проекта. Например, `[agents.qa-verifier]` с `config_file` задаёт другой источник
роли. Сохраните эти настройки и уберите дублирующие объявления перед новой
проверкой. Скрипт сам их не меняет. Дополнительные переопределения ролей через
CLI `-c` после проверки использовать нельзя.

Если существует `/etc/codex/config.toml`, он тоже проверяется. Облачные настройки
организации эта локальная проверка не подтверждает: при их наличии необходимо
отдельно проверить фактические роли в клиенте до делегирования.

При работе через плагин выбирайте именно его через `@`. При работе через отдельный
скилл отключите плагин в клиенте и выберите `$agent-flow` из отдельной установки.
Проверьте абсолютный путь `package_root` в выводе `check-installed-package.py`.
Не выбирайте обе формы в одном запросе. Если клиент не позволяет однозначно выбрать
источник, сначала отключите лишнюю форму; не продолжайте делегирование с неясным источником.

### Обновление скилла, установленного через npx

Перед обновлением сохраните весь установленный скилл, настройки Codex и роли
в резервной папке вне каталогов установки. Skills CLI может заменить целевой
каталог; пользовательские добавления сохраните в копии и сравните перед переносом.
Повторите установку через npx и настройку ролей из раздела выше. Разберите
показанные конфликты, проверьте пакет и откройте новый чат. Задачи предыдущей установки не продолжаются и не мигрируются. To Do, Lessons и Implementation Notes остаются обычными файлами проекта.

### Обновление плагина

До обновления найдите фактический установленный каталог через
`codex plugin list --json`. Скопируйте весь каталог этого плагина в кэше,
включая сохранённые версии и локальные добавления, в отдельную резервную папку
вне кэша Codex. Проверьте совпадение
содержимого файлов, символических ссылок и прав доступа. Отдельно сохраните
настройки Codex и пользовательские роли. Если копия неполна, остановитесь:
штатная установка заменяет каталог плагина и может удалить старые версии в кэше.
Старый ZIP не содержит пользовательских добавлений.

Распакуйте новый архив в новый постоянный каталог:

```sh
codex plugin marketplace remove agent-flow
codex plugin marketplace add "/новый/постоянный/каталог/agent-flow"
AF_PACKAGE="$(codex plugin add agent-flow@agent-flow --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["installedPath"] + "/skills/agent-flow")')"
python3 "$AF_PACKAGE/scripts/sync-codex-agent-config.py" --output-dir "$HOME/.codex/agents"
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --dependencies
```

Начните новую задачу. Локальная сборка получает детерминированный суффикс
`+codex.<хеш снимка>`, пронумерованный выпуск - ровно `X.Y.Z`.
Новая версия выбирает новый кэш Codex. Сохраните старый архив
и резервную копию до успешной проверки в новой задаче. Локальные добавления
переносите только после сравнения, не перезаписывая файлы нового пакета.
Git-updater отдельного скилла к плагину не применяется.

Удаление плагина выполняется через `codex plugin remove agent-flow@agent-flow`.
Оно не должно удалять отдельный скилл и пользовательские роли. Генератор не выдаёт
свои TOML за автоматически зарегистрированные клиентом роли: новую задачу нужно
создать после настройки.

## Сборка и проверки

Для разработки сначала выполните [подготовку окружения и подключение pre-commit](development.md).

Из исходного Git checkout:

```sh
python3 skills/agent-flow/scripts/check-all.py
python3 scripts/build-plugin.py --output "/каталог/вне/репозитория"
```

Сборщик собирает рабочий пакет детерминированным обходом разрешённых каталогов
(`agents`, `references`, `registries`, `scripts`, `docs/en`, `docs/ru`,
`docs/assets`) и создаёт один
ZIP плагина без изменения исходников. Повтор с теми же входами даёт те же байты;
записанный архив перечитывается и сверяется со свежим снимком исходников.
Тестовые данные, тестовые скрипты, кэши, исторические implementation/ADR
и резервные копии в поставку не входят.

Из распакованной копии проверьте состав:

```sh
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --package-only
```

Полный `check-all.py` требует исходный Git checkout; установленную копию проверяйте
её собственными скриптами. Успех проверки архива не подтверждает реальные QA/reviewer
или вызов через `@`. Пронумерованные выпуски собираются и проверяются на GitHub
только из тегов `vX.Y.Z`.
