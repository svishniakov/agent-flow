# Установка Agent Flow

Document status: done

Обе поставки используют один пакет. Плагин содержит дополнительный манифест и
каталог установки Codex. Python 3.11 или новее нужен для скриптов настройки.
Node.js и Skills CLI нужны только для установки командой `npx skills add`.

## Готовый ZIP из Releases

Откройте [последний выпуск](https://github.com/svishniakov/agent-flow/releases/latest).
В разделе Assets выберите `agent-flow-X.Y.Z-skill.zip`, JSON с окончанием
`-build.json` и файл `-SHA256SUMS.txt` той же версии. Скачайте все три файла
в отдельную папку. ZIP содержит готовый скилл; исходный репозиторий не нужен.
До первого пронумерованного выпуска список Releases будет пуст.

В папке со скачанными файлами выполните:

```sh
shasum -a 256 -c agent-flow-*-SHA256SUMS.txt
```

Обе суммы должны совпасть. В JSON проверьте `version`, `release_tag` и
`commit_sha`: они должны соответствовать выбранному выпуску и его коммиту.
Распакуйте ZIP. Перенесите папку `agent-flow` в `~/.agents/skills/`, чтобы файл
оказался по пути `~/.agents/skills/agent-flow/SKILL.md`.
Если там уже есть файл, папка или символическая ссылка `agent-flow`, сначала
сохраните прежнюю установку целиком вне каталога скиллов. Не распаковывайте
новую версию поверх старой и не переносите пользовательские правки без сравнения.

Затем выполните:

```sh
AF_PACKAGE="$HOME/.agents/skills/agent-flow" &&
python3 "$AF_PACKAGE/scripts/check-agent-deps.py" --post-install &&
python3 "$AF_PACKAGE/scripts/sync-codex-agent-config.py" --output-dir "$HOME/.codex/agents" &&
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --dependencies
```

Разберите показанные конфликты ролей и недостающие зависимости по инструкциям
скриптов. Начните новую задачу Codex и вызовите `Agent Flow`. Для обновления
скачайте следующий выпуск и повторите эти шаги с резервной копией старой установки.
Git-updater не обновляет установку из ZIP.

Пронумерованные выпуски создаются отдельно. Обычный push сохраняет сборки в Actions.

## Сборки после push

Откройте [GitHub Actions](https://github.com/svishniakov/agent-flow/actions/workflows/push-build.yml),
выберите успешный запуск `Push checks and distributions` и сверьте его commit SHA
с нужным коммитом. В разделе Artifacts скачайте результат с именем
`agent-flow-<версия>-<полный SHA>-run<RUN>-attempt<ATTEMPT>`.
Он хранится 14 дней, если политика репозитория не ограничивает срок сильнее.
При падении проверки устанавливаемого результата нет.

Распакуйте скачанный artifact в пустой каталог. В нём должны находиться два ZIP,
JSON с метаданными сборки и файл с окончанием `-SHA256SUMS.txt`.
Из этого каталога выполните:

```sh
shasum -a 256 -c *-SHA256SUMS.txt
```

При несовпадении суммы остановитесь и скачайте результат заново. В JSON проверьте
исходный commit SHA и версию `X.Y.Z-dev.RUN.ATTEMPT`; они должны соответствовать
выбранному запуску. Затем распакуйте нужный ZIP в новый постоянный каталог
и выполните инструкции ниже. Оба ZIP содержат одну редакцию общего пакета.

Это предварительная версия ниже стабильной `X.Y.Z` по SemVer. Переход со стабильной
версии на такую сборку выполняется явной переустановкой из выбранного архива.
Автоматическое обновление со стабильной версии не обещается. Для следующей сборки
используйте раздел обновления: новый источник плагина, повторная настройка ролей,
проверка установленного пакета и новая задача Codex обязательны.

## Отдельный скилл

Для новой глобальной установки из GitHub:

```sh
npx skills add https://github.com/svishniakov/agent-flow -a codex -g &&
python3 ~/.agents/skills/agent-flow/scripts/check-agent-deps.py --post-install &&
python3 ~/.agents/skills/agent-flow/scripts/sync-codex-agent-config.py --output-dir ~/.codex/agents
```

Для готового архива проверьте SHA-256 по `SHA256SUMS.txt` и распакуйте файл
с окончанием `-skill.zip` в отдельный постоянный каталог. Следующие команды
устанавливают копию только в текущий проект. Целевой каталог должен отсутствовать;
для существующей установки используйте раздел обновления ниже.

```sh
test ! -e .agents/skills/agent-flow &&
test ! -L .agents/skills/agent-flow &&
npx skills add "/постоянный/каталог/agent-flow" --skill agent-flow --agent codex --copy --yes &&
AF_PACKAGE="$PWD/.agents/skills/agent-flow" &&
python3 "$AF_PACKAGE/scripts/check-agent-deps.py" --post-install &&
python3 "$AF_PACKAGE/scripts/sync-codex-agent-config.py" --output-dir "$PWD/.codex/agents" &&
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --roles-dir "$PWD/.codex/agents" --dependencies
```

При ошибке цепочка останавливается до следующего шага.
Глобальные скиллы и роли эти команды не меняют. В новой задаче напишите
`Agent Flow` или выберите `$agent-flow` из установленной копии.

## Плагин Codex

Проверьте SHA-256 архива по приложенному `SHA256SUMS.txt`. Распакуйте файл с окончанием
`-codex-plugin.zip` в постоянный каталог. В распакованной папке `agent-flow` должны
быть `.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json` и `skills/agent-flow`.
Название каталога установки внутри Codex всегда `agent-flow`.

```sh
codex plugin marketplace add "/постоянный/каталог/agent-flow"
AF_PACKAGE="$(codex plugin add agent-flow@agent-flow --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["installedPath"] + "/skills/agent-flow")')"
codex plugin list --json
```

Команда получает `installedPath` из ответа Codex и сохраняет путь установленного
скилла в `AF_PACKAGE`. Путь версии кэша меняется при обновлении.

```sh
python3 "$AF_PACKAGE/scripts/check-agent-deps.py" --post-install
python3 "$AF_PACKAGE/scripts/sync-codex-agent-config.py" --output-dir "$HOME/.codex/agents"
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --dependencies
```

Создайте новую задачу Desktop. В поле запроса введите `@`, выберите установленный
Agent Flow и отправьте задачу. Выбор плагина означает явный вызов его основного
скилла. Обычный запрос без выбора и текстового маркера не должен запускать процесс.

## Роли и конфликты

Генератор сохраняет эталон последней синхронизации в `.agent-flow-baseline.json`
рядом с TOML ролей. Перед записью проверяется весь набор. Чужой одноимённый файл,
ручная правка управляемого файла, повреждённый эталон или символическая ссылка
останавливают команду до первой записи. Пути конфликтов выводятся в ошибке.

Сохраните конфликтующие файлы в своей резервной копии. Сравните их с новой ролью;
если решили заменить конкретный файл, перенесите его из каталога ролей и повторите
синхронизацию. Не удаляйте весь каталог `agents`. Старые файлы без эталона можно
принять только при полном совпадении с новой генерацией; их байты не переписываются.
Файлы с прежним служебным заголовком и отличающимся содержимым тоже сохраняются.

`--check` проверяет настройку без записи. Повторная синхронизация неизменного
пакета безопасна. Проверка пакета также обнаруживает несовпадающие роли проекта,
которые могли бы перекрыть глобальные. Недостающие дополнительные скиллы показаны
отдельным отчётом; установка пакета не подключает сервисы и не устанавливает их молча.

## Выбор одной формы и обновление

Проверка также останавливается при явных объявлениях ролей Agent Flow в
`config.toml`, включая именованные профили (`$CODEX_HOME/<имя>.config.toml`)
и настройки родительских каталогов
проекта. Например, `[agents.qa-verifier]` с `config_file` задаёт другой источник
роли. Сохраните эти настройки и уберите дублирующие объявления перед новой
проверкой. Скрипт сам их не меняет. Дополнительные переопределения ролей через
CLI `-c` после проверки использовать нельзя.

Если существует `/etc/codex/config.toml`, он тоже проверяется. Облачные настройки
организации эта локальная проверка не подтверждает: при их наличии необходимо
отдельно проверить фактические роли в клиенте до делегирования.

При работе через плагин выбирайте именно его через `@`. При работе через отдельный
скилл отключите плагин в клиенте и выберите `$agent-flow` из отдельной установки.
Проверьте абсолютный путь `package_root` в выводе `check-installed-package.py`.
Не выбирайте обе формы в одном запросе. Если клиент не позволяет однозначно выбрать
источник, сначала отключите лишнюю форму; не продолжайте делегирование с неясным источником.

### Обновление отдельного скилла из архива

Skills CLI перед повторной установкой очищает целевой каталог. Чтобы сохранить
пользовательские файлы, сначала перенесите прежнюю копию целиком в уникальный
каталог вне `.agents/skills`. Команды предназначены для копии, установленной
выше с `--copy`; символическую ссылку они не заменяют.

Из корня проекта, после распаковки нового архива в новый постоянный каталог:

```sh
test -d .agents/skills/agent-flow &&
test ! -L .agents/skills/agent-flow &&
AF_BACKUP="$(mktemp -d "$PWD/agent-flow-backup.XXXXXX")" &&
mv .agents/skills/agent-flow "$AF_BACKUP/agent-flow" &&
npx skills add "/новый/постоянный/каталог/agent-flow" --skill agent-flow --agent codex --copy --yes
```

Продолжайте только после успеха этой цепочки. Выполните проверки пакета и настройку
проектных ролей из раздела установки. Прежние пользовательские файлы остаются
в `$AF_BACKUP/agent-flow`; не переносите их поверх файлов нового пакета без
сравнения. Конфликт ролей разбирается по правилам выше, до делегирования.
Сохраните резервную копию и старый архив до успешной проверки в новой задаче.
Git-updater не обновляет копию, установленную из ZIP.

### Обновление плагина

До обновления найдите фактический установленный каталог через
`codex plugin list --json`. Скопируйте весь каталог этого плагина в кэше,
включая сохранённые версии и локальные добавления, в отдельную резервную папку
вне кэша Codex. Проверьте совпадение
содержимого файлов, символических ссылок и прав доступа. Отдельно сохраните
настройки Codex и пользовательские роли. Если копия неполна, остановитесь:
штатная установка заменяет каталог плагина и может удалить старые версии в кэше.
Старый ZIP не содержит пользовательских добавлений.

Распакуйте новый архив в новый постоянный каталог:

```sh
codex plugin marketplace remove agent-flow
codex plugin marketplace add "/новый/постоянный/каталог/agent-flow"
AF_PACKAGE="$(codex plugin add agent-flow@agent-flow --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["installedPath"] + "/skills/agent-flow")')"
python3 "$AF_PACKAGE/scripts/sync-codex-agent-config.py" --output-dir "$HOME/.codex/agents"
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --dependencies
```

Начните новую задачу. Локальная сборка получает детерминированный суффикс
`+codex.<хеш снимка>`, сборка GitHub - версию `X.Y.Z-dev.RUN.ATTEMPT`.
Новая версия выбирает новый кэш Codex. Сохраните старый архив
и резервную копию до успешной проверки в новой задаче. Локальные добавления
переносите только после сравнения, не перезаписывая файлы нового пакета.
Git-updater отдельного скилла к плагину не применяется.

Удаление плагина выполняется через `codex plugin remove agent-flow@agent-flow`.
Оно не должно удалять отдельный скилл и пользовательские роли. Генератор не выдаёт
свои TOML за автоматически зарегистрированные клиентом роли: новую задачу нужно
создать после настройки.

## Сборка и проверки

Для разработки сначала выполните [подготовку окружения и подключение pre-commit](development.md).

Из исходного Git checkout:

```sh
python3 scripts/check-all.py
python3 scripts/build-distributions.py --output "/каталог/вне/репозитория"
```

Сборщик читает явный список `skills/agent-flow/package-files.txt` и создаёт два
ZIP без изменения исходников. Повтор с теми же входами даёт те же байты.
Список содержит рабочую документацию, роли, скрипты и синтетические тестовые данные;
исторические implementation/ADR, кэши, резервные копии и пользовательские добавления
в поставку не входят. При добавлении ресурса обновите список и запустите полный набор.

Из распакованной копии проверьте состав:

```sh
python3 "$AF_PACKAGE/scripts/check-installed-package.py" --package-only
```

Полный `check-all.py` требует исходный Git checkout; установленную копию проверяйте
её собственными скриптами. Успех проверки архива не подтверждает реальные QA/reviewer
или вызов через `@`. Сборки GitHub Actions доступны по инструкции в начале страницы.
