# Работа с Agent Flow

Agent Flow координирует явно порученную задачу и проверяет её результат. Для запуска добавьте `Agent Flow` в запрос. Чтение или обсуждение скилла не запускает процесс.

## До работы

Укажите цель, ограничения и существующий план или задачу. Agent Flow читает нужные части To Do, Lessons и Implementation Notes, затем исходники. Существенные вопросы требований и архитектуры решаются до зависимых правок.

Для изменения файлов выберите в задаче уникальный заголовок и подраздел «Критерии приёмки» с плоским списком. Требования остаются в исходном документе. В журнале хранится ссылка на этот раздел.

## Выполнение

Работа идёт в выбранном checkout. Журнал хранит пути области работы и ссылку на выбранный раздел требований. Он не сканирует репозиторий и не отслеживает изменения файлов. Дополнительный worktree нужен только при реальной необходимости изоляции.

Основной агент может писать код сам. Отдельных исполнителей подключают для независимой работы с понятными границами. Один путь одновременно имеет одного автора.

Каждый субагент возвращает один отчёт в собственном завершённом ответе; основной агент регистрирует свой отчёт из текущего turn. SQLite принимает отчёты после проверки фактической сессии и доказательств. Дополнительные handoff-файлы, lane-map, timeline и копии сводок не создаются. Markdown-вид получается при чтении.

## Проверка

Для положительного завершения изменения файлов нужны независимые reviewer и QA в этом порядке. Reviewer проверяет реализацию и отчёты авторов. QA связывает критерии с фактическими проверками результата и указывает ID назначения принятого reviewer.

Проверяются исходники, реальные команды, cwd, exit и output. После собственных содержательных исправлений исполнители повторяют затронутые проверки и review. Журнал не обнаруживает изменения автоматически; работа в соседнем чате не отменяет приёмку этой задачи.

Каждый автор отчитывается о своей работе и своих путях, без объяснения посторонних изменений репозитория. Пользовательские правки сохраняются точечным редактированием и ревью. SQLite защищает записи журнала, но не откатывает внешние действия.

## Завершение и память

Final появляется только в конце: `completed` либо `failed` с причиной и неподтверждённой частью. Финальный ответ оркестратора содержит вывод по отчётам, проверки и ограничения.

To Do, Lessons и Implementation Notes остаются обычной постоянной памятью проекта. Они обновляются напрямую и не зеркалируются в SQLite. Исторические отчёты агентов не нужны новой задаче.

После обновления пакета синхронизируйте роли и откройте новый чат. Поддержки прежних форматов и миграций нет; пользовательские архивы автоматически не удаляются.
